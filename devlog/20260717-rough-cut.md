## 1. Review verdict on the initial approach

The 0716 doc was audited claim-by-claim against the local checkouts before any
code was written. Every load-bearing claim held: prim.js's geometry switch,
scene.js's no-XR render-per-tick, the bus's presence-based filters and
`{registered:true}` init hook, `mulberry32` in utils, and the live
`pose.position` binding (`three-helper.js` rewrites the pose to the node's own
vectors, which is what makes grab-and-move free).

**Open question §12.1 is now answered.** Nested manifest recursion works:
manifest entries without a `resolve` are re-dispatched through `bus.resolve()`,
so an entry `{load:[...]}` re-enters the loader. The caveat is real, though —
the loader resolves relative specs against `document.baseURI` (the page), *not*
the manifest's own URL. So the importmap-alias scheme (`here/`,
`orbital-volume/`) is **required**, not a nicety. Confirmed working.

**A gotcha the 0716 doc missed, now load-bearing project style:** module
namespace objects iterate their exports *alphabetically*, not in source order.
A manifest with named exports therefore dispatches in surprise order (camera
before scene = boot error). **Every agent file exports one `default` array**;
array order is dispatch order. `agents/all.js` exports `default { load:[...] }`.

Also confirmed: the published CDN bus needs `@orbitalfoundation/utils` in the
importmap too (the bus imports it as a bare specifier). orbital-volume's own
demo page already models this; our importmap does the same.

## 2. Decision: raw WebAudio, our own declarative sound service

Considered: adopt a third-party engine (Tone.js) vs. build the `sound` service
on raw WebAudio. **Decision: raw WebAudio.** Reasons:

1. The valuable thing here is the *declarative component schema and handler
   table* — that is ours to build either way. Tone would sit underneath it as a
   second abstraction layer, not replace it.
2. Tone's core asset is its Transport/scheduling model — which is precisely the
   concept this project replaces with spatial primitives (movers as playheads,
   §3). We would be fighting its clock with ours.
3. The actual audio graph per voice is four nodes. Zero dependencies keeps the
   service ~180 lines, build-free, and cleanly extractable as `orbital-sound`.
4. The decision is *reversible at the handler table*: a future
   `synth:'tone-something'` handler could delegate to Tone for fancy
   instruments without touching the component schema or any app code.

## 3. The primitive ladder (stepwise goals; Ableton → space mapping)

Discussed 0717: crystals currently embody everything and are stationary. The
richer idea set — moving blobs that follow paths, resonance between crystals,
effects as crystals wrapping crystals — decomposes into an additive ladder.
Each rung is one new agent file (+ occasionally a new row in the sound
service's handler table); no rung rewrites a lower one.

- **P0 — voice + latch** (== M0, built): stationary crystals, toggle by
  pass-through/reticle. Prove the field sounds like a place.
- **P1 — ping**: one-shot excitation of the same voice (attack-release instead
  of sustain). Prerequisite for anything that "plays" crystals.
- **P2 — mover**: an entity whose position follows a path, pinging crystals it
  intersects. The path *is* the pattern, the speed *is* the tempo — a visible
  playhead. Natural extension: record the player's own walked trajectory and
  replay it as a mover — a loop pedal for movement.
- **P3 — resonance**: a ringing crystal faintly excites same-pitch-class
  neighbours (sympathetic strings / sends). Pure taste, zero architecture.
- **P4 — enclosure = routing**: a shell wrapping a crystal inserts an effect on
  its voice; a big shell around a cluster is a group bus; nesting is chaining.
  Spatial containment == signal-chain containment.

**Two seams were built into M0 so this ladder stays refactor-free** (both in
`services/sound.js`):
- `excite()` is the single excitation entry point — the latch drives it today;
  P1's ping is just a second caller.
- every voice terminates in a plain `output` gain before master — P4's wrapping
  is disconnect/reconnect at that node.

And `interaction.js`'s toggle test is "a position and a radius", not "the
player", so P2's mover reuses it verbatim.

## 4. What was built (M0 rough cut)

Everything in the 0716 doc's §4 layout except `vendor/` and `deploy/`:
`index.html` (importmap), `index.js` (bus + load), `services/sound.js` (the
peer service: voice/listener handlers, lazy voices, HRTF panners, envelope
ramps, manual quaternion→orientation math so it has no three.js dependency),
`agents/{all,config,stage,field,interaction,hud}.js`, and
`scripts/render.mjs` (headless verification harness).

orbital-volume was extended per §7 (committed on its `main`):
- `crystal` geometry in prim.js — tetra/octa/icosa by `facets`, seeded
  `displaceVertices` (hash-by-position so non-indexed faces stay welded).
- **display-driven clock**: `volume.clock: true` on the scene entity makes the
  surface own the tick loop via `renderer.setAnimationLoop` (identical to rAF
  outside XR, required inside it). Opt-in; `{run:'realtime'}` apps untouched.
- `bus.volume.surface()` accessor so peers never touch `_surfaces` internals.
